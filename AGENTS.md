# Bach Bench Site

Start with an issue. Make the change on a branch, run `npm run check`,
then open a pull request. That command builds, checks types, lints and
inspects the built pages. Merge after the checks pass. GitHub Actions deploys
the merge and checks its commit at bach.wlkr.si. Keep the historical asset
URLs available through the original custom-domain Worker.

The Site contains no Pieces, media, Workshop code or private run records.
Read the catalogue from the Vault. Never publish
attempt counts, opinions about Pieces or rankings of the music. Use the term
Piece. Show the recorded picture and sound at full quality.

Keep the navigation minimal. Use quiet text buttons and restrained links.
Avoid pill buttons, underlined back links, and lines under section headings.
On Listen, the player is the exception: a round white play button carrying
the rainbow glow, icon buttons for the other controls, and a scrubber. Keep
every control at least 44 px and inside the first screen on phones.
Keep existing table row lines. Use the white Listen button with its rainbow
glow once per screen. Keep Anthropic, OpenAI, xAI and Google on one line in
chart exports. Place the lab legend inside the chart, highlight that lab's
models on hover or tap, and put the italic description in the footnote.
Keep PNG, SVG and copy-link actions under the WLKR.SI mark. Use Analysis as
the page name. Fix layout before adding explanatory copy.

Use builds, type checks, lint and narrow page integrity checks. Prove visible
changes on the real site. Keep automated test suites out of this repository.
